# ZeroTally（keep-accounts）设计系统规范

本规范定义应用的视觉基调、设计令牌与使用边界，所有页面组件只能通过 `useTheme()` 引用语义令牌，禁止在组件内硬编码色值或随意偏离尺度。

## 品牌气质决策

| 维度 | 决策 | 具体落地 |
| --- | --- | --- |
| 严肃与轻快 | 偏向冷静克制 | 中等圆角（8/12/16px）、无花哨装饰，突出资金数据可读性 |
| 传统与现代 | 现代极简 | 遵循系统无衬线字体，配合冷灰阶中性色提高数字清晰度 |
| 紧凑与舒展 | 清晰留白 | 卡片内边距 16px、分组外间距 24px（组外间距大于组内间距） |
| 品牌色与语义色 | 玉青主色 + 清晰收支语义 | 主色深玉青 `#0D9488`（操作态浅色 `#017853` / 深色 `#28CBC0`），支出玫红、收入翠绿、转账晴蓝、负债琥珀 |

## 色彩与无障碍约束

1. **三档文字层级**：正文字（`text`）、次级说明（`textSecondary`）、弱化辅助（`textMuted`），不再新增第四档灰字。
2. **彩色底禁止放灰字**：总览卡片（`heroBg`）上的辅助标签使用同色相浅阶 `heroSubtext`（`#98fffc`），而非透明度灰白字。
3. **深色模式以明度表层级**：页面底 `neutral.950`（`#11121f`，禁用纯黑 `#000000`），卡片 `neutral.900`（`#222435`），输入与浮层 `neutral.800`（`#35394c`）。
4. **不单靠颜色传递语义**：支出固定带 `-¥` 前缀、收入带 `+¥` 前缀、转账带 `转出 -> 转入` 文案；所有 34 组浅色与深色前背景配对均已通过 `check_contrast.py` WCAG AA 4.5:1 校验（34/34 通过）。

## 尺度系统与用法

- **字号**：`12 / 14 / 16 / 18 / 20 / 24 / 30 / 36` px（卡片金额主数字用 `30-36`，列表标题用 `16`，次级信息用 `12-14`）。
- **字重**：仅使用两档 `400`（正文与常规标签）和 `600`（标题、金额数字与主按钮）。
- **间距**：`4 / 8 / 12 / 16 / 24 / 32 / 48` px；同类元素组内用 `8-12`，不同区块之间用 `24`。
- **圆角**：输入与标签 `8`、标准按钮与条目 `12`、卡片 `16`、徽章与悬浮主按钮 `9999`。
- **边框与透明度**：边框仅用 `1px`（分割/轮廓）和 `2px`（选中聚焦）；交互态透明度仅用 `0.45`（禁用）和 `0.78`（按压）。
- **触控热区**：Android 可交互控件最小触控区域 `48 x 48 dp`（通过最小高度或 `hitSlop` 保障）。

## 操作层级金字塔

- 每屏仅保留 **1 个主要操作**（如底栏居中向上凸起的圆形「+ 记一笔」主按钮或表单底部「保存」按钮）。
- 次要操作使用描边或浅底按钮（如「调账」、「新增账户」）。
- 三级或破坏性操作（如「停用」、「删除」）弱化为文字按钮或危险浅底，配合二次确认。

## 令牌扩展原则

- 允许微调既有色阶内某档亮度，但禁止随意新增色阶档位或在组件中写入未入库像素值。
- 若现有语义令牌无法覆盖新场景，先在 `src/theme/design-tokens.json` 补充对比度校验并更新 `src/theme/tokens.ts`，再供业务组件使用。
